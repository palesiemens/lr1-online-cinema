# Архитектура приложения

## Слои

1. **Модели (`models.py`)** описывают данные предметной области и проверяют локальные ограничения полей в `__post_init__`.
2. **Репозиторий (`repository.py`)** реализует универсальные операции Create, Read, Update и Delete над объектами с идентификаторами.
3. **Сервис (`service.py`)** управляет репозиториями, проверяет уникальные бизнес-ключи, внешние связи и ограничения удаления.
4. **Хранилище (`storage.py`)** отделяет формат файла от бизнес-логики. `StorageAdapter` задает общий интерфейс, `JsonStorage` и `XmlStorage` реализуют конкретные форматы.
5. **Консольный интерфейс (`cli.py`)** принимает пользовательский ввод и перехватывает ожидаемые ошибки, не завершая работу программы.

## Модель данных

| Класс | Назначение | Основные связи |
|---|---|---|
| `User` | Пользователь сервиса | Подписки, отзывы, история, избранное, платежи, устройства |
| `Genre` | Жанр | Используется фильмами |
| `Movie` | Фильм каталога | Жанры, отзывы, история просмотров, избранное |
| `SubscriptionPlan` | Тариф | На него ссылаются подписки |
| `Subscription` | Подписка пользователя | Пользователь, тариф, платежи |
| `Review` | Отзыв и оценка | Пользователь и фильм |
| `WatchHistoryEntry` | Запись просмотра | Пользователь и фильм |
| `FavoriteList` | Список избранного | Пользователь и фильмы |
| `Payment` | Платеж | Пользователь и подписка |
| `PromoCode` | Промокод | Самостоятельная сущность справочника |
| `Device` | Устройство пользователя | Пользователь |

## CRUD и бизнес-правила

Единый метод `CinemaService.create()` принимает объект любого поддерживаемого класса. Методы `get()`, `get_all()`, `update()` и `delete()` обеспечивают остальные операции CRUD. Это уменьшает дублирование одинакового кода для одиннадцати типов сущностей.

Сервис проверяет уникальность почты пользователя, названия жанра и кода промоакции. До добавления связанной сущности проверяется существование объектов, на которые она ссылается. Удаление фильма запрещается, если на него ссылаются отзывы, история или избранное; аналогичные ограничения действуют для жанров, пользователей, тарифов и подписок.

## Исключения

- `CinemaError` - базовый класс ошибок приложения.
- `ValidationError` - некорректные значения полей.
- `EntityNotFoundError` - объект с указанным идентификатором отсутствует.
- `DuplicateEntityError` - повтор идентификатора или уникального бизнес-ключа.
- `BusinessRuleError` - нарушение правила предметной области.
- `StorageError` - ошибка файлового ввода-вывода или разбора XML/JSON.

Пользовательский интерфейс дополнительно перехватывает стандартные `ValueError` и `TypeError`, например при вводе букв вместо идентификатора. Ошибка выводится в консоль, после чего меню показывается повторно.

## Форматы хранения

Корневой объект содержит одиннадцать коллекций. Каждая коллекция хранит массив однотипных объектов. Списки идентификаторов жанров и фильмов представляют связи между сущностями. Перечисления сохраняются как строковые значения (`active`, `paid` и т. п.). Даты записываются в ISO 8601.

JSON использует массивы и объекты, XML - корневой элемент `online_cinema`, элементы коллекций и вложенные элементы полей. При чтении значения преобразуются обратно в `int`, `float`, `bool`, `list` и `Enum`, поэтому приложение получает типизированные экземпляры классов, а не наборы строк.
