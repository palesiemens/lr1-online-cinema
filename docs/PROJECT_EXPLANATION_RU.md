# Подробное описание проекта LUMEN

Документ нужен, чтобы самостоятельно ориентироваться в исходном коде лабораторной работы и объяснять преподавателю назначение файлов, классов и основных методов.

## 1. Что моделирует программа

LUMEN — учебная модель онлайн-кинотеатра. Она описывает не воспроизведение реального видео, а данные, которые нужны такому сервису: пользователей, фильмы, жанры, тарифы, подписки, оценки, историю просмотра, избранное, платежи, промокоды и устройства.

Во время работы объекты находятся в оперативной памяти. Пользователь может сохранить весь набор данных в JSON или XML, а затем загрузить его обратно.

Программа разделена на несколько модулей, чтобы классы предметной области, правила, хранение и интерфейс не находились в одном большом файле.

## 2. Как выглядит структура папок

```text
lr1_online_cinema/
├── data/                      примеры сохранённых данных
├── diagrams/                  UML-диаграмма и её исходники
├── docs/                      отчёт и пояснительные документы
├── prototypes/                HTML-прототип интерфейса
├── src/online_cinema/         исходный Python-код
├── tests/                     автоматические тесты
├── .gitignore                 исключения для Git
├── pyproject.toml              настройки Python-проекта
├── requirements.txt            внешние пакеты для тестов
└── README.md                   описание проекта для GitHub
```

### Корневые файлы

- **`README.md`** — главная страница проекта на GitHub. В нём указаны тема, вариант, функции, дерево папок, установка, запуск, тесты, UML и ограничения.
- **`pyproject.toml`** — настройки Python-пакета: имя `online-cinema-lr1`, версия, минимальная версия Python, папка исходников `src` и настройки pytest.
- **`requirements.txt`** — список внешних пакетов. Сейчас в нём указан только `pytest`, потому что остальное приложение использует стандартную библиотеку Python.
- **`.gitignore`** — список файлов, которые Git не должен добавлять в репозиторий: виртуальное окружение `.venv`, кэш Python и pytest, временные папки сборки и настройки IDE.

## 3. Папка `src/online_cinema`

Это основная часть программы. Здесь находится код, который запускается при старте.

### 3.1. `models.py` — классы предметной области

В этом файле описаны 11 основных классов. Большинство объявлены через `@dataclass`: Python автоматически создаёт конструктор и методы сравнения, а поля перечислены прямо в классе.

После создания объекта автоматически запускается `__post_init__`. В нём проверяются значения полей. Например, год выпуска фильма должен быть в заданном диапазоне, длительность должна быть положительной, рейтинг должен быть одним из допустимых значений. Если поле некорректно, выбрасывается `ValidationError`.

**Классы предметной области:**

| Класс | Для чего нужен | Основные поля |
|---|---|---|
| `User` | Учётная запись зрителя | `id`, `full_name`, `email`, `is_active` |
| `Genre` | Жанр фильма | `id`, `name`, `description` |
| `Movie` | Карточка фильма в каталоге | `id`, `title`, `description`, `release_year`, `duration_minutes`, `age_rating`, `genre_ids`, `director`, `cast` |
| `SubscriptionPlan` | Тариф подписки | `id`, `name`, `price`, `duration_days`, `max_devices`, `video_quality` |
| `Subscription` | Подписка пользователя | `id`, `user_id`, `plan_id`, даты начала и окончания, `status` |
| `Review` | Оценка и отзыв на фильм | `id`, `user_id`, `movie_id`, `rating`, `comment`, `created_at` |
| `WatchHistoryEntry` | Запись о просмотре | `id`, `user_id`, `movie_id`, `progress_seconds`, `watched_at` |
| `FavoriteList` | Список избранных фильмов | `id`, `user_id`, `name`, `movie_ids` |
| `Payment` | Платёж за подписку | `id`, `user_id`, `subscription_id`, `amount`, `method`, `status`, `created_at` |
| `PromoCode` | Скидочный промокод | `id`, `code`, `discount_percent`, `expires_at`, `is_active` |
| `Device` | Устройство пользователя | `id`, `user_id`, `device_name`, `device_type`, `last_seen_at` |

**Как связаны объекты:**

- `Movie.genre_ids` хранит идентификаторы жанров, к которым относится фильм.
- `Subscription.user_id` указывает на пользователя, а `plan_id` — на тариф.
- `Review` и `WatchHistoryEntry` ссылаются на пользователя и фильм.
- `FavoriteList.movie_ids` хранит идентификаторы фильмов в списке избранного.
- `Payment` ссылается на пользователя и его подписку.
- `Device` ссылается на владельца устройства.

Связи сделаны через числовые `id`, а не через вложенные объекты. Это упрощает сохранение в JSON/XML и позволяет проверять целостность ссылок.

**Вспомогательные части `models.py`:**

- `SubscriptionStatus` задаёт статусы подписки: `active`, `expired`, `cancelled`.
- `PaymentStatus` задаёт статусы платежа: `pending`, `paid`, `failed`, `refunded`.
- `_check_integer`, `_check_positive`, `_check_amount`, `_check_text` и другие функции проверяют корректность полей.
- `_serialise()` переводит перечисления и вложенные значения в формат, пригодный для записи в файл.
- `_coerce_value()` восстанавливает типы после чтения файла: например, превращает строку `"12"` в число `12`, текст `"true"` — в `True`, а значение статуса — в соответствующий Enum.
- `CinemaData` объединяет все 11 коллекций в один объект. `to_dict()` превращает его в словарь, `from_dict()` собирает объект обратно из словаря.

### 3.2. `exceptions.py` — собственные исключения

Все ошибки приложения наследуются от базового класса `CinemaError`:

- `ValidationError` — неверное значение поля: пустое название, неправильная дата, отрицательная длительность и т. п.
- `EntityNotFoundError` — объект с указанным ID не найден.
- `DuplicateEntityError` — объект или уникальное значение уже существует.
- `BusinessRuleError` — операция нарушает правило предметной области, например нельзя удалить фильм, на который уже есть отзывы.
- `StorageError` — ошибка чтения, записи или разбора файла.

Благодаря общему базовому классу интерфейс может перехватить все ожидаемые ошибки через `except CinemaError` и вывести сообщение вместо аварийного завершения.

### 3.3. `repository.py` — хранение и простые CRUD-операции

В файле находится класс `InMemoryRepository`.

Он хранит объекты одного типа в словаре:

```python
self._items: dict[int, T] = {}
```

Ключ словаря — ID объекта, значение — сам объект. `T` — параметр типа, который позволяет использовать один и тот же класс для фильмов, пользователей, жанров и других моделей.

Методы:

| Метод | Назначение |
|---|---|
| `add(entity)` | Добавляет объект, если его ID ещё не занят |
| `get(entity_id)` | Возвращает объект по ID или выдаёт `EntityNotFoundError` |
| `get_all()` | Возвращает все объекты по возрастанию ID |
| `update(entity_id, entity)` | Заменяет объект с тем же ID |
| `delete(entity_id)` | Удаляет объект и возвращает его |
| `clear()` | Очищает хранилище |
| `__len__()` | Возвращает количество объектов |

Слово `InMemory` означает, что данные находятся в оперативной памяти. После закрытия программы они исчезнут, если предварительно не сохранить их в файл.

### 3.4. `service.py` — правила работы с данными

Здесь находится `CinemaService`. Он создаёт по одному `InMemoryRepository` для каждого класса предметной области и предоставляет общий способ работы с ними.

Основные методы:

- `create(entity)` — добавляет объект, предварительно проверяя уникальность и ссылки.
- `get(model_type, entity_id)` — получает объект заданного типа по ID.
- `get_all(model_type)` — возвращает все объекты выбранного типа.
- `update(model_type, entity_id, **changes)` — создаёт обновлённую копию объекта, повторно проверяет поля и сохраняет её.
- `delete(model_type, entity_id)` — удаляет объект, если другие объекты не ссылаются на него.
- `search_movies(query)` — ищет фильм по названию, описанию или режиссёру.
- `export_data()` — собирает содержимое всех репозиториев в объект `CinemaData`.
- `import_data(data)` — загружает данные в репозитории и повторно проверяет связи.

Дополнительные методы `_check_unique()`, `_validate_relations()` и `_check_delete_restrictions()` выполняют проверки предметной области.

Примеры правил:

- адрес электронной почты пользователя должен быть уникальным;
- название жанра не должно дублироваться;
- фильм может ссылаться только на существующие жанры;
- платёж и подписка должны принадлежать одному пользователю;
- один пользователь не может оставить два отзыва на один фильм;
- нельзя удалить пользователя или фильм, пока на них есть ссылки из других записей;
- нельзя изменить владельца подписки, если к ней уже привязан платёж другого пользователя.

**Почему CRUD находится в двух файлах?** `repository.py` отвечает за простые операции со словарём. `service.py` добавляет к ним смысловые правила. Например, репозиторий умеет удалить фильм по ID, но сервис перед удалением проверяет, что фильм не используется в отзывах, истории и избранном.

### 3.5. `storage.py` — работа с JSON и XML

В файле есть общий абстрактный класс `StorageAdapter` и две реализации:

- `JsonStorage` — сохраняет и загружает файл JSON с помощью модуля `json`.
- `XmlStorage` — сохраняет и загружает файл XML с помощью `xml.etree.ElementTree`.

У обоих классов одинаковые методы:

- `save(data, path)` — записывает `CinemaData` в файл;
- `load(path)` — читает файл и возвращает `CinemaData`.

Это пример наследования и полиморфизма: код интерфейса может работать с общим типом хранилища, а конкретный класс сам выбирает формат.

В XML используются корневой элемент `online_cinema`, коллекции и вложенные элементы `item`. Списки и словари сохраняются рекурсивно. В JSON данные представляются объектом с массивами коллекций.

Важно различать два процесса:

1. **Сериализация** — преобразование объектов Python в структуру JSON или XML и запись в файл.
2. **Десериализация** — чтение структуры файла и восстановление объектов Python с нужными типами.

Если файл отсутствует, повреждён или содержит неподходящие значения, возникает `StorageError`.

### 3.6. `sample_data.py` — начальные данные

Функция `build_sample_data()` создаёт набор демонстрационных объектов: пользователей, жанры, фильмы, тарифы, подписки и связанные записи. Она возвращает один объект `CinemaData`.

Функция `create_sample_service()` создаёт `CinemaService`, передаёт ему тестовые данные и возвращает готовый сервис. Поэтому при запуске программы сразу появляется каталог, с которым можно работать.

Это демонстрационные значения, а не реальные пользователи или реальные платежи.

### 3.7. `cli.py` — консольный интерфейс

Функция `main()` создаёт сервис с демонстрационными данными и объекты `JsonStorage` и `XmlStorage`, затем запускает цикл меню.

Команды меню:

| Пункт | Действие |
|---|---|
| 1 | Показать каталог фильмов |
| 2 | Найти фильм по тексту |
| 3 | Добавить фильм |
| 4 | Изменить описание фильма |
| 5 | Удалить фильм |
| 6 | Сохранить все данные в JSON |
| 7 | Сохранить все данные в XML |
| 8 | Загрузить данные из JSON |
| 9 | Загрузить данные из XML |
| 0 | Завершить работу |

В меню обрабатываются `CinemaError`, `ValueError` и `TypeError`. Например, если вместо ID введено слово или сервис не нашёл фильм, программа печатает ошибку и возвращает пользователя к меню.

Важное уточнение: консольный интерфейс показывает CRUD-операции на примере фильмов. Полный CRUD для всех 11 типов объектов реализован в `CinemaService` и проверяется тестами; отдельные пункты меню для каждой сущности не создавались.

### 3.8. `__main__.py` и `__init__.py`

- `__main__.py` импортирует функцию `main()` из `cli.py` и запускает её. Поэтому команда `python -m online_cinema` начинает работу приложения.
- `__init__.py` отмечает папку как Python-пакет и экспортирует `CinemaService`, чтобы его можно было импортировать из пакета.

## 8. Как проходит добавление фильма

Это пример, который удобно рассказать на защите.

1. Пользователь выбирает пункт 3 в `cli.py`.
2. Программа запрашивает ID, название, описание, год, длительность, рейтинг и ID жанров.
3. Из значений создаётся объект `Movie` из `models.py`.
4. При создании запускается `Movie.__post_init__()`. Он проверяет ID, текст, год, длительность, возрастной рейтинг и список жанров.
5. `cli.py` передаёт объект в `CinemaService.create()`.
6. Сервис проверяет, что каждый указанный жанр существует.
7. `InMemoryRepository.add()` помещает фильм в словарь по его ID.
8. Если проверка не проходит, возникает исключение. `cli.py` перехватывает его и печатает сообщение, а цикл меню продолжает работу.

## 9. Как проходит сохранение в файл

1. `CinemaService.export_data()` собирает все коллекции в `CinemaData`.
2. Пользователь выбирает сохранение в JSON или XML.
3. `JsonStorage.save()` вызывает `CinemaData.to_dict()`, затем использует `json.dumps()` и записывает текст через `Path.write_text()`.
4. `XmlStorage.save()` создаёт корневой XML-элемент и рекурсивно добавляет коллекции, объекты, поля и элементы списков.
5. При загрузке методы `load()` читают файл и передают структуру в `CinemaData.from_dict()`.
6. `from_dict()` восстанавливает конкретные классы и типы полей.
7. `CinemaService.import_data()` загружает объекты в репозитории, повторно проверяя связи.

## 10. Где в проекте показаны принципы ООП

- **Классы и объекты:** класс `Movie` описывает общий набор свойств фильма; конкретный объект хранит данные одного фильма.
- **Инкапсуляция:** поля сущности и проверки этих полей находятся в одном классе; сервис скрывает правила работы с репозиториями за методами `create`, `update`, `delete`.
- **Наследование:** `JsonStorage` и `XmlStorage` наследуются от `StorageAdapter`; все собственные исключения наследуются от `CinemaError`.
- **Полиморфизм:** оба файловых хранилища предоставляют одинаковые `save()` и `load()`, но выполняют операции для разных форматов.

У классов предметной области нет искусственного общего родителя: они описывают разные типы данных. Наследование применено там, где есть общий интерфейс или общий тип ошибки.

## 11. Что установлено и что не нужно устанавливать

Стандартная библиотека Python уже содержит `dataclasses`, `datetime`, `enum`, `json`, `xml.etree.ElementTree`, `pathlib`, `typing` и другие модули, используемые приложением. Отдельно скачивать их не нужно.

Единственный внешний пакет для лабораторной — `pytest`. Установка выполняется из корневой папки проекта:

```powershell
python -m pip install -r requirements.txt
```

Для установки пакета проекта и запуска команды `python -m online_cinema` используется:

```powershell
python -m pip install -e .
```

Подробная инструкция для Windows и GitHub находится в `SUBMISSION_GUIDE_RU.md`.
