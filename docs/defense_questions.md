# Подготовка к защите: ответы на 20 вопросов

Ответы сформулированы на уровне вводной лабораторной работы. Примеры ориентированы на Python и проект «Онлайн-кинотеатр».

## 1. Определение прикладного программирования

Прикладное программирование - разработка программ, предназначенных для решения конкретных пользовательских или предметных задач: учета, обработки данных, автоматизации процессов, управления информацией. Результат - прикладное программное обеспечение, например система онлайн-кинотеатра.

## 2. Особенности разработки прикладного программного обеспечения

Разработчик изучает предметную область и требования пользователей, проектирует модель данных и интерфейс, выбирает технологии, реализует бизнес-логику, проверяет корректность, документирует и сопровождает программу. Важны удобство, надежность, безопасность, поддерживаемость и соответствие требованиям.

## 3. Компилируемые и интерпретируемые языки

Компилируемый язык обычно предполагает предварительное преобразование исходного кода в машинный код или промежуточное представление. Примеры: C, C++, Rust. Интерпретируемый подход выполняет программу посредством интерпретатора во время запуска. Примеры: Python, JavaScript, Ruby. На практике граница не абсолютна: реализация Python CPython сначала компилирует код в байткод, затем виртуальная машина его исполняет.

## 4. Динамическая и статическая типизация

При динамической типизации тип связывается со значением во время выполнения: `x = 10`, затем `x = "текст"`. Примеры: Python, JavaScript, Ruby. При статической типизации типы проверяются до запуска компилятором или анализатором: например, C++, Java, Rust. В Python типы можно дополнительно указывать аннотациями, но они сами по себе не включают статическую проверку во время исполнения.

## 5. Строгая и слабая типизация

Строгая типизация ограничивает неявное смешивание несовместимых типов. Например, Python не складывает строку и число без явного преобразования: `"5" + 2` вызывает `TypeError`. В языках со слабой типизацией чаще встречаются неявные преобразования, например в JavaScript выражение `"5" + 2` дает строку `"52"`. Термины не имеют единственного формального определения, поэтому сравнение зависит от конкретных правил языка.

## 6. Высокоуровневые и низкоуровневые языки

Высокоуровневые языки скрывают детали аппаратуры и предоставляют абстракции: Python, Java, C#. Низкоуровневые языки ближе к архитектуре процессора и управлению памятью: ассемблер, машинный код. C и C++ часто рассматривают как языки системного программирования, сочетающие относительно высокий уровень абстракции с возможностью низкоуровневого управления.

## 7. Изменяемые и неизменяемые типы Python

Изменяемые объекты можно менять после создания: `list`, `dict`, `set`, большинство пользовательских экземпляров. Неизменяемые объекты нельзя изменить на месте: `int`, `float`, `bool`, `str`, `tuple`, `frozenset`, `bytes`. Например, `append()` меняет список, а операция со строкой создает новую строку.

## 8. Операторы, ветвление, циклы и функции

Операторы выполняют вычисления и сравнения: `+`, `-`, `*`, `/`, `//`, `%`, `**`, `==`, `!=`, `and`, `or`, `not`. Ветвление задается `if`, `elif`, `else`. Циклы: `for` и `while`; `break` завершает цикл, `continue` переходит к следующей итерации. Функция объявляется через `def`, принимает параметры и может возвращать результат через `return`.

## 9. ООП: классы, объекты, инкапсуляция, наследование и полиморфизм

Класс описывает структуру и поведение объектов, объект является конкретным экземпляром класса. Инкапсуляция объединяет данные и методы и ограничивает прямой доступ к внутреннему состоянию. Наследование позволяет создавать классы на основе других. Полиморфизм позволяет использовать объекты через общий интерфейс, даже если их реализации различаются. В проекте `JsonStorage` и `XmlStorage` реализуют общий интерфейс `StorageAdapter`.

## 10. `*args` и `**kwargs`

`*args` собирает произвольное число позиционных аргументов в кортеж, `**kwargs` - именованных аргументов в словарь. Пример: `def log(*args, **kwargs): print(args, kwargs)`. Вызов `log(1, 2, level="INFO")` даст `args == (1, 2)` и `kwargs == {"level": "INFO"}`.

## 11. Лямбда-функции

`lambda` создает небольшую анонимную функцию из одного выражения. Пример: `sorted(movies, key=lambda movie: movie.title)`. Для сложной логики лучше использовать обычную функцию `def`, потому что читаемость важнее попытки уместить всё в одну строку.

## 12. Аннотации типов

Аннотации указывают ожидаемые типы параметров, атрибутов и возвращаемых значений: `def get_movie(movie_id: int) -> Movie:`. Они улучшают читаемость, автодополнение и работу статических анализаторов. Python обычно не проверяет их автоматически при каждом вызове функции.

## 13. PEP 8

PEP 8 - руководство по стилю Python. Оно рекомендует отступы в четыре пробела, осмысленные имена в `snake_case` для функций и переменных, `PascalCase` для классов, ограничение длины строк, пробелы вокруг операторов, понятные импорты и последовательное форматирование.

## 14. Классификация ошибок и стандартные исключения

Синтаксические ошибки мешают разобрать программу (`SyntaxError`). Ошибки времени выполнения возникают при исполнении (`ZeroDivisionError`, `TypeError`, `NameError`, `IndexError`, `KeyError`, `FileNotFoundError`). Логические ошибки приводят к неправильному результату, хотя программа формально выполняется. Исключения - механизм представления ошибок времени выполнения.

## 15. Способы обработки ошибок в Python

Основной механизм - `try`, `except`, `else`, `finally`. В `try` помещается потенциально опасный код, `except` обрабатывает конкретные исключения, `else` выполняется при отсутствии исключения, `finally` - в любом случае. Для передачи ошибки выше используется `raise`. Следует перехватывать конкретные ожидаемые исключения, а не скрывать все ошибки общим `except Exception`.

## 16. Базовые исключения Python

`Exception` - базовый класс большинства обычных исключений. Часто встречаются `ValueError` (неподходящее значение), `TypeError` (неподходящий тип), `KeyError` (нет ключа), `IndexError` (индекс вне диапазона), `ZeroDivisionError` (деление на ноль), `AttributeError` (нет атрибута), `FileNotFoundError` (файл не найден), `OSError` (ошибка ввода-вывода).

## 17. Создание собственного исключения

Собственное исключение объявляется наследованием от `Exception` или более специализированного класса: `class ValidationError(Exception): pass`. В проекте определен базовый `CinemaError`, от которого наследуются `ValidationError`, `EntityNotFoundError`, `DuplicateEntityError`, `BusinessRuleError` и `StorageError`. Это позволяет отдельно обрабатывать ошибки предметной области.

## 18. XML, сериализация и десериализация

XML - текстовый формат разметки с тегами, атрибутами и иерархической структурой. Сериализация преобразует объекты программы в XML-представление для хранения или передачи. Десериализация выполняет обратное преобразование. В проекте используется `xml.etree.ElementTree`: дерево создается при записи и разбирается при чтении.

## 19. JSON, сериализация и десериализация

JSON - текстовый формат обмена данными на основе объектов, массивов, строк, чисел, логических значений и `null`. В Python модуль `json` предоставляет `dumps`/`dump` для сериализации и `loads`/`load` для десериализации. Перед записью перечисления преобразуются в строки, а при чтении восстанавливаются типизированные объекты.

## 20. Сравнение XML и JSON

JSON обычно компактнее и удобен для REST API и обмена объектами. XML поддерживает атрибуты, пространства имен, схемы и развитую разметку, что полезно в документно-ориентированных форматах и интеграциях. Оба формата текстовые, независимые от языка программирования и поддерживают вложенные структуры. В данной лабораторной работе оба формата описывают одинаковые одиннадцать коллекций.
