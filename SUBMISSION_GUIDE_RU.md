## 2. Установка Python в Windows

Проект требует Python 3.10 или новее. Для обычного Windows-компьютера скачайте 64-разрядный установщик с официальной страницы:

<https://www.python.org/downloads/windows/>

При установке отметьте пункт **Add Python to PATH**, если он доступен, затем запустите установку. После установки закройте и заново откройте PowerShell.

Проверьте установку:

```powershell
py --version
python --version
```

Достаточно, чтобы команда `py --version` показала Python 3.10 или новее. Если команда `py` не найдена, попробуйте `python --version`. Если не работают обе, перезапустите установщик и включите добавление Python в PATH.

## 3. Установка Git для Windows

Git нужен для фиксации изменений и отправки проекта на GitHub. Скачать его можно с официального сайта:

<https://git-scm.com/install/windows>

Во время установки можно оставить настройки по умолчанию. После установки откройте новое окно PowerShell и выполните:

```powershell
git --version
```

Команда должна вывести установленную версию Git.

## 5. Установка пакетов Python

Во время обычного запуска приложение использует только стандартную библиотеку Python. Отдельно устанавливать пакеты для классов, дат, JSON, XML и файловых операций не нужно.

Для установки проекта в режиме разработки `pip` использует `setuptools` (он указан в `pyproject.toml` как инструмент сборки и при необходимости устанавливается автоматически). Единственный внешний пакет, который нужен непосредственно для проверки проекта, — `pytest`. Он запускает автоматические тесты и не требуется для обычной работы меню.

Выполняйте команды из корневой папки проекта по очереди:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -e .
python -m pip install -r requirements.txt
```

Что делают команды:

- `py -m venv .venv` — создаёт изолированное виртуальное окружение в папке `.venv`;
- `Activate.ps1` — включает это окружение в текущем PowerShell;
- `python -m pip install --upgrade pip` — обновляет установщик пакетов;
- `python -m pip install -e .` — устанавливает сам пакет онлайн-кинотеатра из текущей папки;
- `python -m pip install -r requirements.txt` — ставит `pytest`, указанный в файле зависимостей.

Если PowerShell запрещает запуск файла активации, не меняйте глобальные настройки безопасности Windows. Используйте виртуальное окружение напрямую:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Если вы не активировали окружение, запускайте команды через полный путь к его Python:

```powershell
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\python.exe -m online_cinema
```

## 6. Проверка проекта

### 6.1. Запуск автоматических тестов

Из корневой папки проекта выполните:

```powershell
python -m pytest
```

Ожидаемое сообщение в конце запуска текущей версии:

```text
26 passed
```

Если число тестов изменится после самостоятельных правок, это нормально. Важно, чтобы в конце не было `failed` или `error`.

### 6.2. Запуск консольного приложения

```powershell
python -m online_cinema
```

Откроется меню LUMEN. В нём можно вывести каталог, найти фильм, добавить фильм, изменить его описание, удалить фильм, а также сохранить и загрузить весь набор данных в JSON или XML. Для завершения выберите `0`.

При первом запуске меню получает демонстрационные данные из `sample_data.py`. Сохранение в файлы выполняется через пункты меню 6 и 7, загрузка — через пункты 8 и 9.

### 6.3. Просмотр HTML-прототипа

Откройте файл `prototypes/index.html` двойным щелчком. Он должен открыться в браузере. Установка Python-пакетов для просмотра прототипа не требуется.

### 6.4. Просмотр UML

Изображение диаграммы находится в `diagrams/class_diagram.png`. Исходник `diagrams/class_diagram.puml` можно редактировать в любом текстовом редакторе или открыть в редакторе PlantUML.

## 7. Создание публичного репозитория GitHub

### 7.1. Создать репозиторий на сайте

1. Войдите в свой аккаунт на <https://github.com/>.
2. В правом верхнем углу нажмите `+`, затем **New repository**.
3. В поле **Repository name** укажите `lr1-online-cinema`.
4. В описании можно написать: `Лабораторная работа № 1 по прикладному программированию. Онлайн-кинотеатр на Python`.
5. Выберите **Public**, чтобы преподаватель мог открыть репозиторий без приглашения.
6. Не включайте пункты `Add a README file`, `Add .gitignore` и `Choose a license`: в локальном проекте уже есть README и `.gitignore`.
7. Нажмите **Create repository**.

GitHub покажет страницу Quick setup. Скопируйте HTTPS-адрес нового пустого репозитория. Обычно он выглядит так:

```text
https://github.com/ВАШ_ЛОГИН/lr1-online-cinema.git
```

### 7.2. Открыть папку проекта в PowerShell

Перейдите в корневую папку проекта, например:

```powershell
cd C:\Study\lr1_online_cinema
```

Убедитесь, что вы находитесь именно в ней:

```powershell
Get-ChildItem
```

Вы должны увидеть `README.md`, `src`, `tests`, `data`, `docs` и остальные папки проекта.

### 7.3. Создать собственную Git-историю

Архив для сдачи не содержит старую техническую папку `.git`. Поэтому создайте репозиторий заново и укажите свои данные:

```powershell
git init -b main
git config user.name "Богданов Даниил Алексеевич"
git config user.email "ВАША_ПОЧТА_ИЗ_GITHUB"
git add .
git status
git commit -m "Лабораторная работа № 1: онлайн-кинотеатр"
```

В `user.email` укажите адрес электронной почты, связанный с GitHub, либо адрес `noreply`, показанный в настройках GitHub. Не вставляйте чужую почту и не используйте пример буквально.

Перед `git commit` внимательно посмотрите вывод `git status`. В список не должны попадать `.venv`, `__pycache__`, `.pytest_cache`, персональные пароли или ключи. В проекте есть `.gitignore`, который исключает типовые временные файлы Python.

### 7.4. Связать локальный проект с GitHub и отправить его

Подставьте скопированный HTTPS-адрес вместо примера:

```powershell
git remote add origin https://github.com/ВАШ_ЛОГИН/lr1-online-cinema.git
git remote -v
git push -u origin main
```

При первом `push` GitHub может запросить авторизацию в браузере через Git Credential Manager. Войдите в собственный аккаунт. Обычный пароль от аккаунта GitHub не следует вставлять в консоль как пароль Git.

Если появилось сообщение `remote origin already exists`, выполните:

```powershell
git remote set-url origin https://github.com/ВАШ_ЛОГИН/lr1-online-cinema.git
git push -u origin main
```

### 7.5. Как должен выглядеть репозиторий для преподавателя

Откройте опубликованную ссылку в браузере в режиме инкогнито или выйдите из GitHub. Если страница и файлы открываются без входа, репозиторий публичный.

На главной странице преподаватель должен увидеть:

- название `lr1-online-cinema`;
- короткое описание проекта;
- файл `README.md` с темой, составом проекта, установкой и командами запуска;
- папки `src`, `tests`, `data`, `diagrams`, `prototypes`, `docs`;
- `pyproject.toml`, `requirements.txt` и `.gitignore`.

README должен отображаться прямо на странице репозитория под списком файлов. Это первая инструкция для проверяющего: что за программа, как её установить, как запустить тесты и приложение.

### 7.6. Проверить отправку

После публикации выполните:

```powershell
git status
git log -1 --oneline
git remote -v
```

После успешной отправки команда `git status` должна сообщать, что рабочее дерево чистое. В браузере откройте список файлов и проверьте, что на GitHub появились исходники, тесты, данные, диаграмма и отчёт.

Скопируйте публичный URL без окончания `.git`, например:

```text
https://github.com/ВАШ_ЛОГИН/lr1-online-cinema
```

Вставьте его в подраздел 3.8 отчёта вместо строки `[ВСТАВИТЬ URL ПОСЛЕ ПУБЛИКАЦИИ НА GITHUB]`. Сохраните DOCX и заново экспортируйте PDF. Затем замените обе версии отчёта в папке `docs` и пересоберите ZIP проекта.

## 10. Ограничения и примечания

- В приложении используются только стандартные модули Python. `pytest` нужен для тестов, а не для запуска самого онлайн-кинотеатра.
- HTML-прототип является статическим макетом. Он не подключён к Python-приложению, серверу, реальному каталогу фильмов или платёжной системе.
- Данные приложения хранятся в оперативной памяти и по команде пользователя сохраняются в JSON или XML. Это учебная модель без внешней базы данных.
- В приложенном образце отчёта структура титульного листа и разделов использована как образец. Если преподаватель требует отдельный официальный файл `Шаблон для ЛР 2024.docx`, его нужно дополнительно сверить с версией отчёта.
